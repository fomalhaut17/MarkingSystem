[ 문제 해결 ]

▶ 앱 실행 직후 API 오류
  Mock 서버가 아직 기동 중입니다. 잠시 후 재시도하세요.

▶ PLC 연결 실패
  Mock 서버 창이 닫혀 있습니다. run.bat을 다시 실행하세요.

▶ 포트 이미 사용 중 (프로세스 충돌)
  작업 관리자에서 MarkingSystem.Mock 프로세스를 수동 종료 후 run.bat을 재실행하세요.

▶ 포트 이미 사용 중 (다른 프로그램 점유)
  appsettings.dev.json에서 포트를 변경하세요.
    Mock.Api.Port  : HTTP API 포트 (기본 47300)
    Plc.Tcp.Port   : TCP PLC 포트  (기본 47200)
  API 포트 변경 시 같은 파일의 Api.BaseUrl 포트도 함께 수정해야 합니다.
  (단, 소스 빌드 환경이 필요합니다)

■ 시나리오 1 — 기본 발행 흐름 (자동 완료)
  Mock PLC가 모든 항목을 처리하면 시스템이 자동으로 결과 대기 상태로 전환되는 흐름이다.
  1. [테스트 초기화] 버튼을 눌러 이전 데이터를 초기화한다
  2. 로그인 화면에서 업체코드 MANTEC / ID admin / PW 1234 입력 후 로그인
  3. 물류 바코드 입력란에 12345678901234 입력 후 Enter
     - 좌측 패널에 품명·제조일자·용기 내 수량·Lot 코드 표시 확인
     - 우측 목록에 10개 행이 NotIssued 상태로 표시 확인
     - [발행 시작] 버튼이 노란색(대기)으로 활성화 확인
  4. [발행 시작] 클릭
     - [발행 시작] 버튼이 파란색(동작)으로 전환, [발행 종료] 버튼이 노란색으로 활성화 확인
     - 목록 행들이 Pending → OK / AD 순으로 자동 채워지는 것 확인
     - Mock PLC는 90% 확률 OK, 10% 확률 AD로 응답
  5. 모든 행의 검사가 완료되면 시스템이 자동으로 결과 대기 상태로 전환
     - [발행 시작] 버튼이 회색(비활성화)으로 전환 확인 (미처리 항목 없음)
     - [발행 종료] 버튼이 파란색(동작)으로 전환 확인
     - [불량 처리], [결과 저장] 버튼이 노란색으로 활성화 확인
  6. [결과 저장] 클릭
     - 모든 버튼 비활성화(회색) 확인
     - 상태 메시지에 OK/NG 건수 표시 확인

■ 시나리오 2 — 발행 중 수동 종료 후 재개
  모든 항목이 완료되기 전에 [발행 종료]를 눌러 중간에 멈춘 뒤 다시 재개하는 흐름이다.
  용기 내 수량이 많은 12345678901234(10개)로 테스트하면 여유가 생긴다.
  1. [테스트 초기화] 버튼을 눌러 이전 데이터를 초기화한다
  2. 시나리오 1의 2~4단계를 동일하게 진행 (발행 시작까지)
  3. 목록 행이 일부 채워지는 동안 [발행 종료] 클릭
     - 진행 중인 항목(Pending) 처리가 완료될 때까지 잠시 대기 후 결과 대기 상태로 전환 확인
     - 아직 처리되지 않은 항목(NotIssued)이 목록에 남아 있는 것 확인
     - [발행 시작] 버튼이 노란색(대기)으로 활성화되어 있는 것 확인 (미처리 항목 존재)
  4. [발행 시작] 클릭하여 나머지 항목 발행 재개
     - 이전에 OK/AD 처리된 항목은 그대로 유지되고 NotIssued 항목부터 이어서 진행되는 것 확인
     - 모든 항목 완료 후 시나리오 1과 동일하게 결과 대기 상태로 전환 확인

■ 시나리오 3 — 미처리 항목 존재 시 결과 저장 차단
  발행을 중간에 종료했을 때 NotIssued 항목이 남아 있으면 결과 저장이 비활성화되는지 확인한다.
  1. [테스트 초기화] 버튼을 눌러 이전 데이터를 초기화한다
  2. 시나리오 1의 2~4단계를 동일하게 진행 (발행 시작까지)
  3. 목록 행이 일부 채워지는 동안 [발행 종료] 클릭
     - 결과 대기 상태로 전환 확인
     - NotIssued 항목이 목록에 남아 있는 것 확인
  4. [결과 저장] 버튼이 회색(비활성화) 상태인 것 확인
     - NotIssued 항목이 남아 있는 한 결과 저장 불가
  5. [발행 시작] 클릭하여 나머지 항목 모두 완료
  6. [결과 저장] 버튼이 노란색(대기)으로 활성화되는 것 확인 후 클릭

■ 시나리오 4 — 불량 처리
  1. [테스트 초기화] 버튼을 눌러 이전 데이터를 초기화한다
  2. 시나리오 1의 2~6단계를 진행하여 결과 대기 상태로 진입한다
  3. 목록의 AD 또는 OK 행 체크박스 선택
  4. [불량 처리] 클릭
     - 양품(OK) 항목이 포함된 경우 경고 메시지 확인
     - 최종 확인 다이얼로그에서 [예] 선택
  5. 선택 행이 NG로 변경되고 불량 카운트 증가 확인
  6. [결과 저장] 클릭

■ 시나리오 5 — 동일 Lot 연속 처리
  12345678901234와 11111111111111은 같은 Lot 코드(P2063121-B1-A:SHVB26073)에 속한다.
  첫 번째 바코드를 처리·저장한 뒤 두 번째 바코드를 조회하면 Ser가 이어져야 한다.
  1. [테스트 초기화] 버튼을 눌러 이전 데이터를 초기화한다
  2. 12345678901234 조회 → 발행 시작 → 발행 종료 → 결과 저장
     - Ser 000001 ~ 000010 발행됨
  3. 11111111111111 조회
     - 좌측 패널의 최종 발행 Ser. 값이 000010으로 표시 확인
     - 목록이 000011 ~ 000020 범위로 채워지는 것 확인

■ 시나리오 6 — 재조회 복원 (앱 재시작)
  발행 중간에 앱이 종료된 경우 다시 시작해도 이전 상태가 복원되는지 확인한다.
  1. [테스트 초기화] 버튼을 눌러 이전 데이터를 초기화한다
  2. 12345678901234 조회 → 발행 시작 → 발행 종료 (결과 저장 안 함)
  3. 앱 강제 종료 후 run.bat 재실행
  4. 로그인 후 12345678901234 다시 조회
     - 새 시리얼이 생성되지 않고 기존 발행 이력이 그대로 복원되는 것 확인
     - [결과 저장] 버튼이 활성화된 상태로 진입 확인
  5. [결과 저장] 클릭하여 정상 저장 확인
